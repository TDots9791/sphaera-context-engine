- ❌ Запрос по содержанию ТСН → движок нашёл 2 кандидата и ОБА ОТБРОСИЛ:

Причина нуля: blob слишком большой/размытый для упаковки в бюджет → ретривер его дропает.

## 1. Задача
Документы (PDF/сканы/xlsx: ТСН, ПД/РД, ФСНБ, приказы — 897 PDF / 6.3 ГБ в `docs/`) должны
стать ДЁШЕВО и БЫСТРО НАВИГИРУЕМЫ: запрос отдаёт КОНКРЕТНУЮ страницу/раздел/таблицу с локатором,
а не весь документ. Отдельно от кода (не раздувать код-граф).

## 2. Требуется — ДОКУМЕНТ-AWARE ЧАНКИНГ (ядро)
Одна PDF → МНОГО evidence-записей с ДОКУМЕНТНЫМИ локаторами (не `L1-Lβ`):
- **страница**: `{file, page}` — запись на страницу (или скользящее окно N стр с перекрытием);
- **раздел/заголовок**: из структуры документа (закладки/TOC/нумерация «Глава 10», «п.5.2») —
  локатор `{file, section_path}`;
- **таблица**: `{file, page, table_idx, [row,col]}` — таблицы отдельными записями (не плоский
  текст), со структурой строк/колонок/шапки;
- **рисунок/чертёж**: `{file, page, region}` — опц., подпись/легенда.
Каждая запись — свой fingerprint (дедуп), провенанс, УМЕЩАЕТСЯ в бюджет пакета (ретривер больше
не дропает). Гранулярность настраиваема (`--doc-granularity page|section|table`).

## 3. Требуется — сопутствующее
- **RU-лемматизация в ретриве документов** (ru-lemma в дефолт): падежи/аббревиатуры/шифры
  (ГЭСН/ФЕР/ТСН-2001.10, «1599-22-ИОС4.2»); языковой провенанс у записи.
- **Сканы → OCR-путь**: много ТСН — сканы; либо OCR-извлечение (опц. компонент), либо честная
  пометка `needs_ocr` (не молчаливый пропуск).
- **Лимит размера по умолчанию для документов** — поднять/снять (7 МБ PDF не должен молча
  выпадать); либо не считать документ «большим файлом» как код.
- **ИЗОЛЯЦИЯ**: отдельный документный адаптер/граф (или отдельный `--root docs`), чтобы код-граф
  оставался лёгким; кросс-ссылки код↔документ — опц. позже.

## 4. Мост к УЖЕ существующей гранулярности (быстрый выигрыш)
У хоста (UniParPro) ПАРСЕР УЖЕ даёт page/table-level чанки (`data/intermediates/ocr_chunks/
<pdf>/page_NNN.json` — 233 стр на один ИОС4.2, с регионами/таблицами/локаторами). Поддержать
**`sphaera import`** этих чанков как документного графа (адаптер `host-docchunks`): маппинг
page_NNN.json → записи `{file,page,table,region}` с провенансом. Это даёт гранулярный
документный граф для УЖЕ распарсенных ПД/РД БЕЗ ожидания полного docingest — и одновременно
пилот формата §2-бенчмарка на RU-документах.

## 5. Критерии приёмки
- Запрос «ТСН-2001 гл.10 нормы на титульные здания» на индексе ТСН → отдаёт КОНКРЕТНУЮ
  страницу/раздел (локатор `{file,page/section}`), `effective_mode` НЕ inventory-пусто,
  `evidence_items>0`, дроп по размеру исчез.
- Запрос по таблице ТСН → отдаёт запись-ТАБЛИЦУ с локатором `{file,page,table_idx}`, а не
  плоский текст всего файла.
- Импорт host-чанков (§4): 233 стр ИОС4.2 → 233+ гранулярных записей; запрос по позиции ВОР →
  конкретная страница-источник.
- Код-граф не задет (отдельный адаптер/root); размер стора растёт пропорционально контенту,
  без blob-дропов.
- RU: запрос с падежами/шифром находит норму (лемма-нормализация видна в провенансе).

## 6. Порядок
1. **§4 мост host-чанков** (быстрый гранулярный доксграф для распарсенных ПД/РД — сразу польза).
2. **§2 документ-aware чанкинг** нативного docingest (страница→раздел→таблица).
3. **§3 RU-лемма + OCR-путь + лимит**.
Всё проверяемо `--format json`; каждая доработка — с замером (дроп-рейт, evidence_items,
savings) на RU-наборе (ТСН/ПД).
