# ТЗ — Sphaera: ЕДИНЫЙ ЖИВОЙ граф знаний (код + документы) + визуализация v1

Статус: НА РЕАЛИЗАЦИЮ. Дата: 2026-07-23. Исполнитель: GPT-5.6 Terra.
Родитель: [[sphaera-commercial-product]]. Соседи (строить НА них): `sphaera_document_graph_granular_v1`
(гранулярные документные узлы — ФУНДАМЕНТ), `sphaera_competitive_hardening_v1` §9 (документный ров),
`sphaera_supergraph_federation_v1` (кросс-проектный слой — потом).

## 0. Идея (владелец)
Нужен ГРАФ ДОКУМЕНТОВ (любых форматов) в ЕДИНОМ полотне с кодом. Рёбра РОЖДАЮТСЯ ИЗ РАБОТЫ:
парсим документ, редактируем, СОЗДАЁМ НОВЫЙ со ссылкой на уже существующий в графе, или пишем на
СХОДНУЮ тему → появляются связи. На выходе — ВИЗУАЛЬНЫЙ граф: и кодовый, и документарный, и связи
между ними. Это «живая карта знаний проекта», а не статический индекс.

## 1. МОДЕЛЬ УЗЛОВ (слои)
- **code**: файл/символ/модуль (адаптеры index/project-map — есть).
- **document**: документ + его гранулярные части (страница/раздел/таблица — из
  `sphaera_document_graph_granular_v1`). Любой формат (PDF/xlsx/md/docx/скан).
- **entity**: доменные сущности, упоминаемые и там, и там (норма ГЭСН/ТСН, объект «1599-22»,
  шифр «ИОС4.2», ГОСТ) — мост между кодом и документами.
Каждый узел: id/тип/локатор/провенанс/язык/fingerprint (дедуп).

## 2. МОДЕЛЬ РЁБЕР — «живость» (ядро)
Рёбра с ТИПОМ, ВЕСОМ, ПРОВЕНАНСОМ (кто/что/когда создал ребро) и способом вывода:
- **contains** — документ→страница→раздел→таблица; модуль→символ (структурные).
- **mentions / cites** — текст документа A ссылается на документ B / норму / шифр / объект.
  Источник: кросс-документные ссылки (у хоста УЖЕ есть, [[reference-layer-universal]]) +
  извлечение цитат/шифров из текста. Ребро document→document|entity.
- **derived_from / edited** — АКТИВНОСТЬ: создан новый документ со ссылкой на существующие →
  ребро new→refs; правка документа → версия/ребро. Источник: `observe`/`lineage` от агента-
  исполнителя (я/Terra/GLM) в момент действия. ЭТО и есть «рождается из работы».
- **similar_topic** — близость по эмбеддингу ≥ θ (порог от риска), с confidence. Не «всё со
  всем»: топ-K + порог + дедуп; помечать как СЛАБОЕ ребро (иначе шум).
- **co_reference** — два документа/файла ссылаются на ОДНУ entity → неявная связь через сущность.
- **implements / documents** — код-узел реализует то, что описано в документе (мост код↔док):
  по общей entity/шифру/имени. Даёт «где в коде живёт норма из ТСН гл.10».
Провенанс ребра обязателен (для аудита и чтобы отличать факт-цитату от догадки-сходства).

## 3. «ЖИВОЕ» ОБНОВЛЕНИЕ
- `watch` + `observe`: при парсинге/правке/создании документа хост эмитит событие →
  инкрементально добавляются узлы/рёбра (не полная пересборка).
- Идемпотентность по fingerprint; устаревшее инвалидируется (fingerprint изменился) — не копится.
- Слабые рёбра (similar_topic) пересчитываются лениво/по запросу, не в каждом цикле.

## 4. ВИЗУАЛИЗАЦИЯ (то, чего просит владелец)
- `sphaera graph viz --root . [--focus <node>] [--layers code,document,entity]
  [--edge-types mentions,derived_from,similar_topic] [--depth N] [--out graph.html]` →
  ИНТЕРАКТИВНЫЙ граф (self-contained HTML): слои цветом, рёбра по типу (сплошные=факт,
  пунктир=сходство), клик по узлу → окрестность, фильтры, поиск.
- **Подграф-вокруг-узла** обязателен: 28k+ узлов целиком не рисуем; фокус + глубина + фильтр.
- Слой-переключатель: только код / только документы / оба + мосты код↔документ.
- Экспорт в стандартные форматы (GraphML/JSON/DOT) для внешних вьюеров (Gephi/Cytoscape).
- Встроенный `dashboard` расширить панелью графа (уже есть HTML-дашборд).

## 5. КРИТЕРИИ ПРИЁМКИ
- Узлы document/entity появляются рядом с code; запрос «граф вокруг ТСН-2001.10» → подграф:
  документ-разделы + code-узлы, реализующие эту норму (мост implements), + документы, что её
  цитируют (mentions).
- Создание нового документа со ссылкой на существующий → в графе появляется ребро derived_from/
  mentions БЕЗ полной пересборки (живость), с провенансом «создано агентом X в TS».
- `graph viz --focus <node> --depth 2` → self-contained HTML с фокус-подграфом, слоями и
  фильтрами; открывается в браузере, читаем.
- similar_topic не превращает граф в «кашу»: порог/топ-K, слабые рёбра помечены, дроп-рейт мерим.
- Изоляция производительности: документный/сущностный слой не тормозит навигацию по коду.

## 6. ПОРЯДОК
1. Фундамент — гранулярные документные узлы (`sphaera_document_graph_granular_v1`, мост host-чанков).
2. Рёбра mentions/co_reference/implements (факт-связи, из существующих ссылок/шифров).
3. `graph viz` (подграф-фокус, слои, фильтры) — минимальная визуализация.
4. Живость (observe/watch активность → derived_from/edited).
5. similar_topic (эмбеддинги, порог) — последним (самое шумное).
Всё проверяемо `--format json` + HTML; каждое ребро — с провенансом; замер шума/полезности.
